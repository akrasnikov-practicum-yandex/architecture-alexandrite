# architecture-alexandrite

Проектная работа по архитектуре ПО — система ювелирной компании **«Александрит»**.

## О системе

«Александрит» производит ювелирные изделия по индивидуальному дизайну: клиент загружает 3D-модель или собирает её в конструкторе, заказ проходит расчёт стоимости и производство. Система состоит из трёх приложений, общающихся через брокер сообщений:

| Приложение | Стек | Назначение |
|---|---|---|
| **Online Shop** | Vue + TypeScript + Three.js / **Shop API** (Java Spring Boot) | Витрина, 3D-редактор, оформление заказа |
| **CRM** | Vue + TypeScript / **CRM API** (Java Spring Boot) | Интерфейс продавцов, подтверждение производства |
| **MES** | React + TypeScript / **MES API** (C# .NET) | Интерфейс операторов, расчёт цены, внешний партнёрский API |

Инфраструктура: **RabbitMQ** (интеграционная шина), **PostgreSQL** (Shop DB, MES DB), **S3** (3D-файлы). Жизненный цикл заказа — 10 статусов от создания до закрытия (см. [sequence-диаграмму](Task1/order_sequence.md)).

После открытия API партнёрам система столкнулась с потерей заказов, задержками и каскадными сбоями при отсутствии наблюдаемости. Решения ниже последовательно закрывают эти проблемы.

## Сквозные принципы решения

- **Три столпа observability**: метрики (Prometheus + Grafana + AlertManager, Task2) → трейсинг (OpenTelemetry + Jaeger, Task3) → логирование (ELK + Vector, Task4), связанные единым `correlation_id = order.id`.
- **Приоритизация по боли бизнеса**: сперва надёжность RabbitMQ и видимость, затем масштабирование и технический долг (Task1).
- **Безопасность по умолчанию**: redaction PII, OIDC SSO + RBAC, mTLS, шифрование at-rest.
